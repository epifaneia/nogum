# NOGUM

[![puertas](https://github.com/epifaneia/nogum/actions/workflows/puertas.yml/badge.svg)](https://github.com/epifaneia/nogum/actions/workflows/puertas.yml)

*Léelo en [español](README.es.md).*

**NOGUM is a tabletop role-playing game. This repository is the compiler for its bilingual 221-page manual, with automatic content validation, and the web app that configures a game from it.**

The product is a universal role-playing game. What is interesting from here is the problem: keeping **four products derived from one source, in two languages, with data shared between a book and an app**, from drifting apart. This repository is the pipeline that solves it and the validation gates that watch it.

🔗 **[Read it published](https://epifaneia.dev/nogum/)**: [the idea](https://epifaneia.dev/nogum/idea.html) · [the book](https://epifaneia.dev/nogum/juego.html) · [the app](https://epifaneia.dev/nogum/app.html)

![The app with a configured table: tone Primera marcha, Tactical danger, a custom world with maximum level 3 and the item catalogue that world uses](img-readme/app-mesa-configurada.png)

> **Why it is here.** The principle of [Epifaneia](https://epifaneia.dev) is that *the model interprets and deterministic code verifies*. This is that principle taken to the limit in a domain where the specification was mine from top to bottom: 221 pages, two languages, four outputs and an app that consumes data from the book itself.
>
> The three things it demonstrates are the same ones a regulated process asks for. **Traceability:** every rule records where it comes from, and the design log is at entry 189, each decision with its reason. **Automatic verification:** the gates stop the build when the content and the data stop saying the same thing. **And deliberate restriction of the model:** the configurator is deterministic because a twenty-question tree solves that better than a model, and the assistant's context is cut so that it never reads the working log.
>
> The underlying problem is the same one [CTSM](https://github.com/epifaneia/ctsm) tackles between a customer requirement and a supplier document: two texts that should say the same thing and stopped doing so, without anyone noticing. The difference here is that the corpus is large, alive and bilingual, and that the gates have been running for months.

---

## The problem

One source feeds four outputs that easily contradict each other:

| Piece | What it is | Format |
|---|---|---|
| La Idea | the design argument, 16 pages | book |
| Juego completo | the manual, 221 pages (223 in English) | book |
| Acelerado | the short version, 23 pages | book |
| App | the configurator and the character sheets | single-file app |

Each book comes out as web and as PDF, and the PDF in two versions: for screen and for printing at home. That is twelve PDFs per build.

The three books are assembled from the same fragments. The app consumes **data extracted from those fragments** (equipment catalogue, optional rules, world recipes). And everything exists in Spanish and in English.

There are many silent ways to break it: renaming a concept in the manual and not in the app's data; fixing a figure in one language and not in the other; removing an item from a list and leaving six references pointing at its neighbour.

## How it is solved

### Build

```
src/assemble3.py          the three books, two languages, three destinations
src/build_app3.py         the app
src/extract_app_data.py   extracts data from the manual for the app
src/extract_firmas.py     the manual's catalogue of signatures, for the app
src/make_covers.py        covers
src/imagenes.py           images, at the web's sizes (uses Pillow)
src/pdf/imprime.mjs       the PDFs, with headless Chrome, like the book's «Print» button
src/pdf/marcadores.py     bookmarks and metadata for each PDF (uses pypdf)
```

Three destinations with different links (local folder, artefacts, public site), resolved at build time, not by hand.

### Validation gates

Nothing is published without going through here:

- **`src/w_revision.py`**: sweeps the compiled products for retired vocabulary, checks the system's invariants and looks for broken anchors, duplicate identifiers and links between pieces.
- **`src/w_marcas_inv.py`**: an inventory of trademarks and names under copyright in what is published, with their context.
- **Build-time assertions**: the number of recipes matches the number of ceiling tables; the catalogue of optional rules is still 18, because the game code uses 18 bits; the twenty worlds of the shortcut point at the twenty recipes once each; the JSON document embedded in the app is still valid.
- **`src/curvas.py`**: the system's probability model, checked against the manual's own printed tables. The eight tables of Appendix B give 56 rows compared per language and 0 discrepancies, and **`src/w_apendice_b.py`** checks it again on every build. The book's SVG charts also come from there, generated from the data and not drawn by hand.

Three examples of failures these gates found that no human reading had seen: a catalogue that dealt a retired damage value **only in the English version**; text that the app carried with vocabulary the manual had already changed; and two output paths that were the same file on Windows, so that the published links pointed at local copies that did not exist.

Each gate exits with a non-zero code if it finds anything, and continuous integration ([`.github/workflows/puertas.yml`](.github/workflows/puertas.yml)) builds and runs them on every push. CI also checks that `docs/`, the published site, is exactly what the source produces: if someone changes a fragment and does not rebuild, or edits `docs/` by hand, it fails and says which file drifted.

It was uncovered by the sweep that `w_revision.py` was born from.

## The app

A self-contained HTML file, with no dependencies and no server.

- **Deterministic configurator**: it sets up the game with questions about situations, not about rules, and from there narrows the catalogue (hundreds of items) down to what that particular world uses.
- **Compressed state**: the whole configuration travels in a short string.
- **IndexedDB** for the audio files the user provides, checking that the file decodes before saving it.
- **A language model** for rules questions, with curated context: the canon document is cut at a marker (`<!-- BITACORA`, `src/app4_body.html`) so that the assistant never reads the working log. The app itself carries the whole canon, the author's quotes included, for the reader to browse; the cut applies only to what is sent to the model.
- **AI with the reader's key (BYOK)**: inside claude.ai it uses the platform's; outside, the key the reader pastes, from one of four providers (Google Gemini, which has a free quota and is the recommended one; Mistral; OpenAI; Anthropic), with no server of its own. For Anthropic its official SDK is loaded from a CDN; the other three are called directly. The key stays in the reader's browser, never travels in any file and by default is forgotten when the tab closes.
- **The table in a file**, with or without the music: configuration, answers, sheets, story and lore, with a version stamp that warns if it is opened with other questions.

On that last point: the configurator is deterministic **on purpose**. A twenty-question tree solves that problem better than a model, and the model is used where it does add something.

## The images

The images were made with **Nano Banana**, Google's image model in the Gemini ecosystem. Claude drafted and rewrote much of the prose, produced the English edition and wrote most of the code. The author's canon governs every rule, and proposals the author has not validated stay marked as such. It is said here and hidden nowhere.

| Series | How many | Where | How they come out |
|---|---|---|---|
| Covers | 5 | the general cover and one per piece (La Idea, Juego completo, Acelerado, App) | colour, at 1280 and 640 px |
| Plates | 26 | in the Juego completo: the thesis, the table, the Director who points, the worlds, optimism, the Anchor, observation, the Grid, the Key, the two purses, danger, choreography, Viper interviewed, the console, the trunk, the tasting menu, the wizard, the ship, the wasteland, the assault on Block C, the singer of Block D, the workshop, the fairy, the court of the Social Duel, the case-file archive and the closed case, under the licence, that ends the book; the thesis also opens La Idea, and the worlds, the Acelerado | colour, at 1400 px |
| Portraits | 12 | the case files of chapter 9, front and profile | grey, at 600 px |

- **Covers.** A series with the same character (hat and coat) and the same studio. The centre is almost black and white and the colour is at the edges.
- **Portraits.** They imitate an old police record. The black band over the eyes is not in the image: the page adds it, at the height each record sets.
- **Charts.** The book's charts are not generated images: they are SVGs that `curvas.py` draws from the data.

The originals are in `src/img/` (`laminas/` and `expedientes/` separately). `imagenes.py` crops them, scales them and, for the portraits, turns them grey, and leaves them in `docs/img/`.

## Responsible use

- **Training data.** The images come from a commercial model whose training data I did not choose and cannot audit: I cannot say whose work it learned from, or whether they agreed. That is why the images are declared, why nothing in the rules or the data depends on them, and why the tables and charts that carry information are computed by `curvas.py` instead of generated.
- **Accessibility.** Every plate that carries meaning has a text alternative in both languages; the covers are marked as decorative. The language switch also changes the page's declared language, so a screen reader changes voice with it. The three books and the app respect reduced motion and dark mode and have a print style, and every PDF carries bookmarks. It has not been tested end to end with a screen reader.
- **Footprint.** A static site with no server, no database and no analytics; the only request to a third party is for the fonts, to Google Fonts. Images are cut to the sizes the web uses, and the app is a single file of about 0.7 MB. A model is called only when a reader asks the app something, with the reader's own key, which by default is forgotten when the tab closes.

## Build it

```bash
mkdir -p NOGUM_productos NOGUM_app    # the output folders, outside docs/
cd src
python extract_app_data.py            # data from the manual -> app
python assemble3.py ../NOGUM_productos # the three books, three destinations
python build_app3.py                  # the app
python w_revision.py                  # the validation gate
python w_apendice_b.py                # Appendix B against curvas.py
python imagenes.py                    # only if an image changes
```

The PDFs, from the root and with a static server on `localhost:8777` (`python -m http.server 8777`):

```bash
node src/pdf/imprime.mjs NOGUM_productos/pdf
python src/pdf/marcadores.py NOGUM_productos/pdf
```

The books and the app build with Python 3's standard library only. The dependencies are for what surrounds them: Pillow for the images, Node and Chrome for the PDFs, and pypdf for their bookmarks.
